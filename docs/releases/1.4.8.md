# Ouicheur 1.4.8

Le service de cadeaux partagé propose désormais une lecture et une sauvegarde pour les coorganisateurs, avec des droits vérifiés sur la liste source et la destination. Le contexte d’autorisation provient du serveur ; ces opérations n’accordent aucun rôle propriétaire. Un hôte peut distinguer explicitement les listes lisibles et celles confiées en coédition. Les droits existants de l’édition auto-hébergée et sa présentation sont conservés.

Les sauvegardes de cette nouvelle interface exigent la version du formulaire pour les envies existantes. Cette version couvre les métadonnées et les offres ; sa comparaison se fait dans la transaction, sous le même verrou que les achats, réservations et autres écritures de cadeaux. Deux connexions ne peuvent pas écraser silencieusement la même version.

Les adaptateurs SQLite et PostgreSQL appliquent les mêmes décisions métier : surprises des destinataires, listes archivées, source et destination autorisées, références de catégories/images et doublons limités au périmètre accessible. Un échec de l’audit annule la mutation. Les services propriétaires existants restent compatibles ; la nouvelle interface de coédition et ses versions sont explicites.

Aucune migration du socle, nouvelle variable d’environnement ou modification intentionnelle de la présentation. Les tests communs, PostgreSQL réel, navigateur et Docker AMD64/ARM64 restent requis avant publication. Cette version n’implémente pas un éditeur de texte collaboratif en temps réel ni un transfert de données vers PostgreSQL.
